## 3. Detailed findings

### F1 — `read_pdf` can crash on `None` page text (P2 bug)
`core/memory/document_memory.py:56`
```python
text += page.extract_text() + "\n"   # extract_text() can return None
```
Some PDFs (scanned/empty pages) make `pypdf` return `None`, raising `TypeError: can only concatenate str`.
**Fix:** `text += (page.extract_text() or "") + "\n"`. Low blast radius (`build_index` is a manual util via
`build_memory.py`) but it's a guaranteed crash on a common input.

### F2 — HUD WebSocket accepts commands from any local origin (P2 security)
`core/hud/ws_server.py:87` (`_handle_client`), `:124` (`_serve`)
The server binds `127.0.0.1` (good — not network-exposed) but performs **no `Origin` validation**. Browsers
*do* allow `ws://127.0.0.1:8765` connections from arbitrary `https://` pages with no CORS preflight, so any
website you visit while Jarvis runs can connect and send `{"type":"text_query"|"pull_model"|...}` — which can
reach `open_app`, `close_app` (taskkill), and `write_file`. This is the classic local-WebSocket / DNS-rebinding
surface.
**Fix:** reject connections whose `Origin` header is a real web origin (allow only `null`/`file://`/absent, which
is what pywebview sends), or require a per-session token passed in the `file://#ws=` fragment and echoed by the
client. ~10 lines in `_handle_client`.

### F3 — Non-atomic JSON persistence (P3 robustness)
`task_storage.save_tasks`, `profile_memory.save_profile`, `semantic_memory.save_memory` all `json.dump`
straight onto the destination file. A crash/power-loss mid-write truncates the file and the next `json.load`
throws. Given CLAUDE.md's emphasis on crash-recovery, this is the weak link.
**Fix:** write to `path + ".tmp"` then `os.replace(tmp, path)` (atomic on Windows & POSIX). One small helper in
`core/paths.py` or a `core/utils/` JSON helper, reused by all three writers.

### F4 — Case & punctuation destroyed before content tools (P3 quality)
`core/speech/engine.py:200` (`clean_query` → `.lower()` + strip non-alnum), `app.py:208` (HUD lowercases too).
Every query is normalized **before** routing, so by the time `write_clipboard(text)` / `write_file(name, content)`
run, the content is already lowercased and stripped of punctuation — "Copy *Hello, World!* to clipboard" stores
`hello world`. Fine for command matching, lossy for content capture.
**Fix:** keep a raw copy of the utterance and pass it to content-bearing tools (thread `raw_query` through
`process_query` → `decide_tool`/`resolve_keyword_tool`, or have those tools receive the unnormalized span).

### F5 — Semantic memory is O(n²) and unbounded (P3 perf)
`core/memory/semantic_memory.py:73` invalidates the cache on every `save_memory`; `:88` then re-encodes the
**entire** memory list on the next `search_memory`. So turn *n* re-embeds all *n* memories, and the JSON file
grows without limit.
**Fix (incremental):** append the new embedding to the cached matrix instead of dropping the whole cache; persist
embeddings alongside text (or in a small FAISS index like the document path already uses). This is also the
v3.5 "memory decay / pruning" roadmap item — worth pulling forward once memory volume grows.

### F6 — TTS `speak()` bypasses the speech lock (P3 concurrency)
`core/speech/engine.py:152` `speak()` launches `_speak_thread` directly (no `speech_lock`), while the TTS-queue
worker speaks via `speak_sync` (`:144`, locked). Both set the shared `current_engine` global. `process_query`
speaks tool responses through `speak()` while LLM sentences flow through the queue → two pyttsx3 engines can run
at once and `stop_speaking()` may target the wrong one.
**Fix:** route *all* speech through the queue (make `speak()` enqueue), or have `speak()` also take `speech_lock`.
Consolidating on the queue is the cleaner design and removes the dual-path entirely.

### F7 — Cross-thread access to module caches (P3 thread-safety)
The HUD `_on_text_query` (`app.py:228`) spawns a `process_query` thread that can run concurrently with the voice
loop's `process_query`. Both touch the unguarded `_cache` dicts in `semantic_memory`/`document_memory` (read in
`search_*`, cleared in `save_memory`). Low probability today (queries are usually serial) but a real data race.
**Fix:** guard the caches with a `threading.Lock`, or serialize `process_query` behind a single worker queue.

### F8–F9 — NLU is brittle (P4 quality)
Reminders only understand minutes (`task_parser.py:10`); personal-info patterns are greedy and fire on every
query (`profile_extractor.py:8`), so "i like to open notepad" both pollutes the profile (`likes = "to open
notepad"`) and proceeds. **Fix:** broaden the reminder grammar (hours/clock times via `dateparser` or a small
regex set) and bound/trim the profile captures (stop at conjunctions, cap length, require a cleaner trigger).

### F10–F14 — Cleanups
- **F10:** delete `wait_until_done()` (dead).
- **F11:** split `_start_hud` (extract the handler-wiring block) and flatten `resolve_keyword_tool` (table-drive the open/close dicts like the substring tools already are).
- **F12:** add the two blank lines in `tests/test_setup_checks.py`.
- **F13:** `os.makedirs(DOCS_PATH, exist_ok=True)` (or early-return) before `os.listdir`.
- **F14:** add `bool`/`float` coercers to `registry._COERCERS` so future tools can declare them.

### F15 — Action gate over-triggers the LLM selector (P4 latency)
`tool_agent._looks_like_action` (`:43`) treats any word matching a tool-name token as actionable, so "should I
**open** up about this?" or "**stop** worrying" pays a 30s-timeout Ollama call before falling back to chat.
**Fix:** require the action verb at a phrase boundary / start, or only treat the registry-name match as a hint
when combined with an imperative shape. Minor — it only costs latency, never correctness.

## 4. Optimizations & upgrades (forward-looking)

| Opportunity | Why | Effort |
|---|---|---|
| Persist memory embeddings (FAISS or cached matrix) | Kills the O(n²) re-encode (F5); instant warm start. | M |
| Route all TTS through the queue | Removes the dual-path race (F6); simpler mental model. | S |
| Atomic JSON writer helper | Crash-safe persistence (F3) across 3 call sites. | S |
| Origin/token auth on the HUD WS | Closes the local-web attack surface (F2). | S |
| Upgrade the LLM model | `phi3` is weak at strict-JSON tool selection; `phi3.5`/`llama3.2`/`qwen2.5` improve `decide_tool` reliability. Just change `MODEL_NAME` + `ollama pull`. | S |
| Stream STT (partial transcripts) | Vosk supports partial results; lower perceived latency + earlier barge-in. | M |
| Type-driven tool arg schema | Generate the `decide_tool` prompt's JSON schema from `ParamSpec` (already structured) for stricter selection. | M |
| Confirmation for destructive tools | `close_app`/`write_file` should confirm when triggered by the (unauth'd) WS path. Pairs with F2. | S |
| Python target clarity | `pyproject` says `>=3.10`; the `speech_recognition`→`aifc` removal warning shows 3.13 needs the `standard-aifc` shim (installed). Pin a tested floor/ceiling and document 3.11–3.13. | S |

**Dependency review:** pins are honest and current for this environment (verified against `pip freeze`).
`websockets` (`>=12.0`, installed `16.0`) and `pywebview` (`>=5.0`, installed `6.2.1`) float while everything
else is exact — consider pinning those two too for reproducible adopter installs, or moving everything to
compatible-range (`~=`) pins. No known-vulnerable versions spotted.
