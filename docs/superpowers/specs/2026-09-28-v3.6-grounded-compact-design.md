# Spec — v3.6 "Grounded & Compact"

> Date: 2026-09-28 · Milestone: v3.6 · Status: design (approved in chat 2026-09-28)
> Branch: `feat/v3.6-grounded-compact` (stacked on `fix/audit-bugfixes` @ `17849d9`)

## Why

A deep audit on 2026-09-28 (inline reading of every module, two verified gap
analyses, headless renders of the HUD) found that Jarvis answers too much from a
small local model that cannot know what it is asked, talks too long, remembers
the wrong things, and hides half its replies from the HUD. The user's goals for
this milestone:

1. Works **offline and online** — online is an enhancement, never a requirement.
2. **File management** across the user's real folders.
3. **Compact** — short replies, compact HUD, lean resource use.
4. **Searching** — local files/documents, and the web when online.
5. **Remembers across sessions** — only what is needed or reusable.
6. **No hallucinations.**
7. **Replies short and to the point** — never a paragraph.
8. **HUD UI fixed** — compact, polished, clean outline and corners.

User decisions (2026-09-28): file scope = workspace + user folders, deletes to
the Recycle Bin behind a confirmation; online = answer from free keyless web
sources; memory = explicit + profile facts only; HUD = compact + visual polish +
outline/corners. Model stays **phi3** (swappable in settings).

## Guardrails (unchanged, every phase)

- Free / local / zero-money. Online calls only to free keyless endpoints
  (Wikipedia, DuckDuckGo Instant Answer, Open-Meteo), behind a settings switch.
- Offline parity: every feature has an offline behaviour that is honest.
- Windows-first; CI (Ubuntu, Python 3.11) stays green — Windows-only code is
  guarded and unit tests never touch a mic, display, network or model.
- Latency: deterministic paths (router → tool) must not call Ollama.
- Privacy: new data files live under `user_data_dir()` and are gitignored.

## Architecture changes (overview)

```
query ──► normalize() ──► process_query
                            │
                            ├─ pending confirmation? (yes/no)       ── conversation.pending
                            ├─ profile capture / reminders           (existing)
                            ├─ resolve_keyword_tool()  ── deterministic, no LLM
                            │     memory · conversation · apps · files · info
                            │     calculator · volume/status/clipboard · search
                            │     weather · lookup
                            ├─ decide_tool()  (skipped when LLM is down)
                            └─ ask_llm()  grounded prompt, 2-sentence cap
                                          │
all replies ──► respond(Reply|str) ──► TTS queue  +  HUD assistant_done
```

New modules: `core/text.py` (normalizer), `core/net.py` (connectivity),
`core/speech/reply.py` (`respond`), `core/state/conversation.py`,
`core/ai/llm_health.py`, `core/agent/info_tools.py`, `core/agent/calc_tools.py`,
`core/agent/memory_tools.py`, `core/agent/web_tools.py`,
`core/agent/known_folders.py`, `core/memory/facts.py`.
Removed: `core/memory/semantic_memory.py` (replaced by `facts.py`).

### Tool return type

Tools keep returning `str`, and may also return `Reply(say, show)` (a frozen
dataclass in `core/agent/registry.py`): `say` is spoken (short), `show` is the
full text for the HUD caption. A keyword-routed tool that returns `None` means
"not handled" and the query falls through to the LLM (used by `lookup` on a
miss).

## Phase 1 — Reliability

### 1.1 `cancel_generation()` (F1)
`core/ai/ollama_engine.py` gains `cancel_generation()`, which bumps the
generation counter. `_stream_response` already abandons a stream whose
generation is stale, closing the HTTP response and skipping `assistant_done`.
Called from `_hud_on_stop`, `_hud_on_text_query` and the wake-word barge-in
branch of `_voice_loop`, each before `stop_speaking()`/`clear_queue()`.

### 1.2 One reply path (F2, F3, F4)
`core/speech/reply.py`:
```python
def respond(reply):
    """Queue a reply for speech and show it in the HUD."""
```
Accepts `str` or `Reply`. Emits `assistant_done(full_text=show)` then
`add_to_queue(say)`. Used by: the tool branch and reminder confirmation in
`process_query`, `TaskManager._fire` (which also emits
`reminder_fired(message=…)`), and both error branches of `ask_llm` (which also
emit `error(message=…)`). `speak()` remains only for the immediate "Yes Boss?"
and "Going back to sleep.". Because replies are now queued,
`wait_until_done_or_barge_in()` covers them and the mic no longer opens over
Jarvis's own voice. The TTS worker emits state `idle` (not `listening`) when the
queue drains; the voice loop already emits `listening` right before it listens.

### 1.3 One normalizer (F5, F6)
`core/text.py` (stdlib only):
- `normalize(text)`: lowercase; curly quotes → straight; drop apostrophes
  ("what's" → "whats"); keep `.` between word characters (`notes.txt`, `3.5`);
  keep `-`, `_`; every other punctuation → space; collapse whitespace.
- `spoken_filename(text)`: "notes dot txt" → "notes.txt", "my file dot p d f" →
  "my file.pdf".

`command()` returns the raw STT text; `_voice_loop` and `_hud_on_text_query`
both call `normalize()` for matching and pass the raw text as `raw_query`.
Router phrase tables are normalized at import. Zero-arg substring tools match on
word boundaries (`\bmute\b`). `_CHITCHAT` in `ollama_engine` uses the same
normalizer. `is_exit_command` runs on the normalized text.

### 1.4 Document index freshness + safe format (F7)
`build_index()` writes `chunks.json` (`[{file, text}]`, replacing `chunks.pkl`)
and a manifest `documents_manifest.json` (`{name: [size, mtime]}` of indexed
PDFs). `_load_index_and_chunks()` compares the manifest with the folder; on a
mismatch or missing manifest it logs once and returns no index (so stale text is
never injected). A legacy `chunks.pkl` is ignored. Rebuild via `build_memory.py`
or the Phase 5 "index my documents" command. `.gitignore` adds the new files.

### 1.5 Log rotation (F8)
`RotatingFileHandler(LOG_FILE, maxBytes=2 MB, backupCount=3, encoding="utf-8")`.

### 1.6 Low-RAM model settings (F9)
`config/settings.py`: `LLM_NUM_CTX = 2048`, `LLM_KEEP_ALIVE = "10m"`,
`LLM_TEMPERATURE = 0.2`, `MODEL_MIN_FREE_GB = 3.5`, `MODEL_PULL_SIZE = "2.3 GB"`.
`num_ctx` + `keep_alive` go into every Ollama payload (`ask_llm`, `decide_tool`,
warmup). `_warm_ollama` skips (logged) when
`psutil.virtual_memory().available` is below `MODEL_MIN_FREE_GB`.
`check_model_present` fails for `:cloud`/`-cloud` tags with a clear message.
The WS `ready` handshake carries `model` + `model_size`; the wizard uses them;
`_hud_on_pull_model` always pulls `settings.MODEL_NAME` (ignores the client);
`_hud_on_save_name` resets wizard mode.

### 1.7 LLM-down fast path (F10)
`core/ai/llm_health.py`: `mark_down(reason)`, `mark_up()`, `is_down()`,
`down_reason()`; state expires after `LLM_DOWN_SECONDS = 30`. `ask_llm` marks
down on a connection error or a non-200, up on success. When down,
`decide_tool` returns `None` immediately and `ask_llm` responds
"My language model isn't available right now. I can still tell the time, do
maths, find files and set reminders." (memory-specific wording when the reason
mentions memory) without an HTTP call.

## Phase 2 — Grounding and short replies

### 2.1 Deterministic info tools (F11)
`core/agent/info_tools.py` (`@tool`s, injectable clock/psutil for tests):
`get_time` ("It's 4:05 PM."), `get_date` ("It's Monday, 28 September 2026."),
`get_day` ("It's Monday."), `battery_status`, `memory_usage`, `disk_space`
(system drive), `uptime`, `network_status`. Router regexes (word-bounded,
question-shaped): "what time is it / whats the time / current time / time
please", "whats the date / todays date", "what day is it / what day is today",
"battery" (≤ 6 words), "ram|memory usage / how much ram", "disk|storage space /
free space", "uptime / how long has my pc been on", "am i online / is the
internet working". Battery phrases move from `system_status` to
`battery_status`.

### 2.2 Calculator (F11)
`core/agent/calc_tools.py`: spoken maths → expression ("plus", "minus",
"times"/"multiplied by"/"x", "divided by"/"over", "to the power of", "squared",
"cubed", "square root of", "N percent of M", "mod"), word numbers ("twenty
five", "one hundred and five", "three point five" — Vosk emits words), then an
`ast` whitelist evaluator (numbers, `+ - * / ** %`, unary minus, `sqrt`;
exponent ≤ 100, expression ≤ 200 chars; no `eval`). Router: "what is / whats /
calculate / compute / how much is <expr>" routes **only if** the whole
expression parses. Reply: `Reply(say="That's 425.", show="25 × 17 = 425")`;
integers print without ".0", floats round to 6 significant digits; division by
zero → "That's undefined."

### 2.3 Grounded prompt + hard reply cap (F12)
Prompt:
```
You are Jarvis, a voice assistant. Reply in one or two short sentences, under 30 words.
Plain spoken English: no lists, markdown or emojis.
Now: {Monday 28 September 2026, 4:05 PM}. Internet: {online|offline}.
[Things the user asked you to remember: …]      (Phase 3, only if relevant)
[Documents (use only if the question is about them): …]
[Recent conversation: …]                          (2.4)
Rules:
- If you are not sure, or it needs live data (news, prices, scores, weather), say you don't know. Never guess.
- You cannot take actions. Never claim you opened, saved, set, sent or changed anything.
- Use remembered facts or documents only when the question is about them.
User: {query}
Jarvis:
```
Options: `temperature` 0.2, `top_p` 0.9, `num_predict` 96, `num_ctx`,
`keep_alive`; stop markers add `"\nUser Profile:"`, `"\nRules:"`. The clock is
injectable. `_stream_response` splits sentences only on `[.!?]` followed by
whitespace (so "3.5" stays whole) and stops after `MAX_SPOKEN_SENTENCES = 2`,
closing the response; the returned text is exactly what was spoken. "Tell me
more / explain more / go on / more details" re-asks the last question with
`detailed=True` (6 sentences, `num_predict` 300). Tool output: `list_files`,
`search_files`, `read_clipboard`, `read_file` speak ≤ 5 names / ≤ 100 chars and
show the full text via `Reply`.

### 2.4 Conversation context (F13)
`core/state/conversation.py`: a module-level, lock-guarded `Conversation`
holding `history` (deque of the last 3 `(user, reply≤200 chars)`), `last_reply`,
`last_query`, `last_results` (paths from file tools) and `pending` (a
confirmation: description, callable, expiry 30 s). Never persisted; cleared when
the session sleeps or expires. `ask_llm` injects history as "Recent
conversation". Deterministic: "repeat that / say that again" → `last_reply`.

## Phase 3 — Memory (explicit + profile facts)

### 3.1 Facts store (F14)
`core/memory/facts.py` → `user_data_dir()/data/memory/facts.json`:
`[{id, text, created, last_used}]`, atomic writes, lock-guarded embedding cache
(the incremental-cache logic and warm-but-empty fix carried over from
`semantic_memory.py`). `add_fact(text)`: cosine ≥ 0.9 to an existing fact →
update it; else append; cap 300 (drop least-recently-used). `search_facts(query,
k=3)` above `MEMORY_SIMILARITY_THRESHOLD`, updating `last_used`.
`find_fact(query)` best match ≥ 0.6. `delete_fact(id)`, `all_facts()`.

### 3.2 Memory commands (`core/agent/memory_tools.py`)
- "remember (that) X / note that X / dont forget (that) X" → `add_fact(X)` →
  "Got it." (show: "Remembered: X").
- "what do you remember (about me) / what do you know about me" → profile +
  5 most recent facts; say ≤ 3 items, show all.
- "whats my <key>" → profile value or "You haven't told me your <key>."
- "forget X" → best fact (or profile key) → pending confirmation "Forget 'X'?
  Say yes to confirm." ; "forget everything" → pending → wipe facts.

### 3.3 Stop saving turns
`process_query` no longer saves LLM turns; `ask_llm` injects `search_facts`
results instead of `search_memory`. `semantic_memory.py` and its tests are
removed; the old JSON file is left on disk untouched (still gitignored).

### 3.4 Stricter profile capture (F15)
Patterns: name ("my name is X", "call me X"), city ("i live in X"), birthday,
job ("i work as a X", "i am a X by profession"), "my favo(u)rite X is Y" →
`favourite_<x>`, goal ("i am preparing for X"), likes ("i like X" → appended to
a list, max 10). Rejected: questions, pronoun/determiner-only values (that, it,
this, those, them, you, him, her), values starting with "to know / to ask / to
see / to hear / if / when / how / what". `get_profile_context` renders lists.

## Phase 4 — Online (free web sources)

### 4.1 Connectivity
`core/net.py` (stdlib only): `is_online()` probes `8.8.8.8:53` then
`1.1.1.1:53`, cached `ONLINE_CACHE_TTL`. `core/speech/engine.py` re-exports it.
Web tools (`search_web`, `open_google`, `open_youtube`) reply "You're offline."
instead of claiming success.

### 4.2 `lookup(topic)` and `weather(city)` (`core/agent/web_tools.py`)
- `lookup`: Wikipedia `w/api.php?action=opensearch&limit=1&search=` → title →
  `api/rest_v1/page/summary/{title}` → first 1–2 sentences of `extract`
  (≤ 40 words), said as "According to Wikipedia, …". Disambiguation pages and
  misses fall back to DuckDuckGo `api.duckduckgo.com/?q=&format=json&no_html=1&skip_disambig=1`
  (`AbstractText`, then `Answer`/`Definition`). Nothing found → `None` (the query
  falls through to the LLM).
- `weather(city)`: Open-Meteo geocoding `geocoding-api.open-meteo.com/v1/search?name=&count=1`
  → `api.open-meteo.com/v1/forecast?latitude&longitude&current=temperature_2m,weather_code&daily=temperature_2m_max,temperature_2m_min,precipitation_probability_max&timezone=auto&forecast_days=1`
  → "In Pune it's 27°C and partly cloudy; high 31, low 22, 40% chance of rain."
  City defaults to the profile `city`; none → "Which city? Say 'weather in <city>'."
  A WMO weather-code table maps codes to words.
- Cache `user_data_dir()/data/cache/web.json` (lookup TTL 30 days, weather
  30 min). Offline: serve cache; nothing cached → "I'm offline and don't have
  that saved." (lookup offline with no cache → `None` → LLM with the grounded
  prompt, which may answer general knowledge or say it doesn't know).
- `requests` with `WEB_TIMEOUT = 4` s and a descriptive User-Agent. Settings
  switch `ONLINE_LOOKUPS = True`.
- Router: "weather / temperature outside / will it rain / is it raining
  (in X)" → weather; "who is/was X", "what is/are X" (≤ 5 words, not maths, not
  a local keyword), "tell me about X", "define X" → lookup.

## Phase 5 — Files and search

### 5.1 Known folders (`core/agent/known_folders.py`)
`SHGetKnownFolderPath` via `ctypes` (Windows) for Desktop, Documents, Downloads,
Pictures, Music, Videos — resolves OneDrive redirection — with a
`Path.home()/<Name>` fallback elsewhere; plus the Jarvis workspace. Only
existing directories are returned. Injectable for tests.

### 5.2 Tools (in `core/agent/fs_tools.py`)
- `find_file(name)`: walk roots with `os.scandir`, depth ≤ 6, ≤ 20 000 entries,
  ≤ 3 s; skip hidden/system dirs, `AppData`, `node_modules`, `.git`, `venv`,
  `__pycache__`; match normalized substring on the name, else `difflib`
  close matches (cutoff 0.75). Results (≤ 10) → `conversation.last_results`.
  Say "Found 3: report.pdf in Downloads, …" (≤ 3), show all with paths.
- `open_file(name)`: an ordinal ("first/second/third/last one") or "it" picks
  from `last_results`; otherwise find and open a single strong match
  (`os.startfile`). Refuses executables/scripts (`.exe .bat .cmd .ps1 .vbs .js
  .msi .com .scr .lnk`) — "I won't run programs from files."
- `open_folder(folder)`: known folder by name.
- `recent_files()`: `%APPDATA%\Microsoft\Windows\Recent\*.lnk` by mtime, top 5
  names.
- `move_file(name, folder)` / `rename_file(name, new_name)`: unique strong
  match required; destination inside the roots; never overwrites; says exactly
  what it did.
- `delete_file(name)`: files only; sets a pending confirmation "Move
  report.pdf from Downloads to the Recycle Bin? Say yes to confirm."; on "yes"
  → `send2trash`. Never a permanent delete.
- Existing workspace tools (`list_files`, `read_file`, `write_file`,
  `search_files`) keep working inside the workspace.

### 5.3 Confirmations
`process_query` checks `conversation.pending` first: "yes / confirm / do it /
go ahead" runs it and responds with its result; "no / cancel / stop" →
"Cancelled."; anything else drops the pending action and routes normally.

### 5.4 Search
- "search for X / look for X / find X in my files" → `search_local(X)`: file
  names (`find_file`) + document chunks + facts; say the top 3 with sources.
  Nothing → "Nothing local for X. Say 'search the web for X' to look online."
- "search the web / google / search google for X" → `search_web` (browser),
  offline-honest.
- "search my documents for X" → `search_documents_tool(X)`: top 2 chunks with
  file names, no LLM. "index my documents" → rebuild the index.

### 5.5 Routing phrases
Open folder: "open (my) downloads|documents|desktop|pictures|music|videos|workspace
(folder)". Find: "find|locate (my|the) X", "where is my X". Open file: "open my X",
"open X.ext", "open the first/second/last one", "open it" (only when
`last_results` is non-empty). Recent: "recent files", "what did i open
recently". Move: "move (my) X to <folder>". Rename: "rename (my) X to Y".
Delete: "delete|remove|trash (my|the) (file) X".

## Phase 6 — HUD

### 6.1 Window chrome — outline and corners (F18)
`hud/window.py`: 380 × 360, `easy_drag=False`, `text_select=True`,
`background_color` = panel colour. On `events.shown`, Windows 11 DWM via
`ctypes`: `DWMWA_WINDOW_CORNER_PREFERENCE (33) = DWMWCP_ROUND (2)` for native
rounded corners and `DWMWA_BORDER_COLOR (34)` = a muted accent for a clean 1 px
native outline; wrapped in try/except (no-op on Windows 10 / other OSes). The
window handle is only touched inside the callback and never stored on a public
`_Api` attribute. CSS: `#panel` loses its radius, border and outer shadow (the
native window provides them). The title bar is the drag region
(`pywebview-drag-region`).

### 6.2 Compact layout
Title bar 28 px: brand · status chip (`● phi3`, green dot online / grey
offline; CPU + battery in its tooltip) · minimize · close. The separate status
row is removed. Stage 120 px when idle; when captions are showing it collapses
to 64 px and the orb scales to 0.5 (transition 0.25 s). Captions take the rest
(~8 lines). Fonts: "Segoe UI Variable Text"; captions 13 px/1.45; chips 11 px.

### 6.3 Captions and states
`.caps { justify-content: safe center }`; follow-scroll while streaming (only
when already near the bottom); `overflow-wrap: anywhere`; caption text is
selectable. No "You:"/"Jarvis:" prefixes — the user line is smaller/dimmer. The
reply pops in on its first token, not again on done. `error` renders in the
fail colour; `reminder_fired` shows as a one-line toast above the input.
Disconnected: `body[data-link=down]` greys the orb, the pill reads
"Connecting…", submit keeps the text in the input and shows "Jarvis core is not
running." Stop is visible while thinking and speaking, and is removed from the
Tab order when hidden (`visibility`). Pill labels: "Say “Hey Jarvis”" (idle),
"Listening…", "Thinking…", "Speaking".

### 6.4 Performance and accessibility
Drop every `backdrop-filter` (the window is opaque, so it only re-blurs the
page's own gradient); static ambient gradient; `#grain` removed; orb blobs
animate `transform` only; `orb.js` stops its rAF loop at level ≈ 0 and restarts
on audio/flash; animations pause while the document is hidden. Reduced motion
disables all animation and the voice scale. `:focus-visible` rings; the input
autofocuses; Esc clears the input first, then stops speech.

### 6.5 Wizard
While the wizard is open the captions/input hide and the stage shrinks, so it
fits in 360 px. A "Re-check" button re-runs checks. The pull button label and
model come from the `ready` handshake. Enter in the name field submits.

### 6.6 Theme first paint
`window.py` adds `&theme=<theme_for_hour(now)>` to the URL fragment; `theme.js`
applies it before first paint; `localStorage` access is wrapped in try/catch.

## Data and privacy

New gitignored paths: `data/memory/`, `data/cache/`, `data/chunks.json`,
`data/documents_manifest.json`. Logs rotate at 2 MB × 3.

## Testing

TDD per task. All CI-safe: `tmp_path` roots and data paths, monkeypatched
clocks/psutil/`requests`/`is_online`, no mic/display/network/model. New test
modules: `test_text.py`, `test_reply.py`, `test_conversation.py`,
`test_llm_health.py`, `test_info_tools.py`, `test_calc_tools.py`,
`test_facts.py`, `test_memory_tools.py`, `test_web_tools.py`,
`test_known_folders.py`, plus extensions to the router, process_query, fs,
document, profile, setup, warmup, window and WS tests. The HUD is verified by
eye with the headless 380 × 360 iframe render (empty, filled, long reply,
disconnected, wizard) and a live run at the end.

## Risks

- **Router over-matching** (e.g. "time" in "last time i…", "what is love" to
  Wikipedia): regexes are anchored to question shapes; the calculator routes only
  on a full parse; lookup phrases are length-bounded; each family has negative
  tests.
- **Destructive file ops from misheard speech:** Recycle Bin only, explicit
  confirmation that expires in 30 s, unique strong match required for
  move/rename, executables never opened.
- **Small-model rule-following:** the prompt helps but the real fix is
  deterministic routing plus the hard 2-sentence cap in code.
- **Third-party lookups** send query text to Wikipedia/DuckDuckGo/Open-Meteo:
  keyless and free, behind `ONLINE_LOOKUPS`, documented in the README.
- **DWM attributes** are Windows 11 only: guarded, no-op elsewhere.
- **Removing `semantic_memory`** drops passive recall of old chats — intended;
  the file stays on disk.

## Deferred (not this milestone)

SQLite FTS content index, Start-Menu app index, organise Downloads, undo
journal, unit conversions, reminders v2 (list/cancel/absolute times), HUD mini
mode, click-to-talk, remembered window position, theme picker.
