# v3.2 — Polish & Packaging — Design

> Status: approved (brainstorming) — ready for implementation plan.
> Date: 2026-05-30. Milestone: v3.2 (PLAN.md "Polish & Packaging").
> Predecessor: v3.2.0 shipped the Desktop HUD (note: the HUD shipped ahead of
> this packaging milestone).

---

## 1. Goal & scope

Make jarvis-py **shippable as a Windows desktop app** and **robust** in the
field. Full scope: both the portable packaging work *and* the
robustness/first-run work, in one milestone.

**In scope**
- A single path resolver that owns all path resolution (bundled assets vs.
  writable user data), so the app works when frozen by PyInstaller.
- PyInstaller **one-folder** (`--onedir`) Windows build bundling the Vosk +
  wake-word ONNX models, plus the HUD web assets.
- Writable user data under **`%APPDATA%\JarvisAI`** when frozen; unchanged repo
  `data/`/`logs/` in dev.
- A **first-run setup wizard** rendered in the HUD: prerequisite checks
  (Ollama, model, microphone, WebView2), guided `ollama pull phi3`, and name
  capture.
- **Auto-HUD on first run only**: a fresh install force-launches the HUD to run
  the wizard regardless of the `--hud` flag; later launches respect the flag.
- **Crash-recovery / graceful degradation** for the four failure modes:
  Ollama down, no microphone, model-load failure, TTS engine death.
- **Microphone auto-detect** (pick a working default input device).
- Build tooling (`jarvis.spec`, `build.ps1`) + README build/smoke-test docs.
- Unit tests for all portable seams; CI stays Ubuntu-only and green.

**Out of scope (explicitly)**
- Bundling Ollama or the phi3 weights (~2.3 GB) — the user installs Ollama and
  pulls a model; the wizard *guides* this but does not ship it.
- A Windows CI build job — the `.exe` build is manual and documented.
- An installer/code-signing/auto-update (those are v5.0).
- Any change to the voice/LLM/memory behavior beyond error handling.

**Constraints (from CLAUDE.md)**
- Free / local / zero-money only.
- Windows-first; the resolver/checks degrade to no-ops on other platforms.
- Never bundle user data or models into git; `.gitignore` stays authoritative.

## 2. Architecture decision

The milestone hinges on **how the HUD window runs when frozen**. Chosen approach
(**A — "Resolver + in-process HUD"**):

- One new `core/paths.py` is the single source of truth for paths.
- The shipped HUD launch model (`subprocess.Popen([sys.executable, "-m",
  "hud"])`) is **kept for dev/source**; **when frozen**, the HUD runs
  **in-process** (pywebview on its own thread), because `sys.executable` is
  `Jarvis.exe` in a frozen build and `-m hud` is unavailable.
- The frozen-specific logic is confined to one launch branch plus `core/paths.py`.

Rejected: (B) making pywebview always in-process — more blast radius on the
already-shipped, deliberately-isolated subprocess HUD; (C) splitting into two
milestones — contradicts the chosen full scope.

## 3. Components

### 3.1 `core/paths.py` — path resolver (foundation)

```python
def is_frozen() -> bool:                 # getattr(sys, "frozen", False)
def resource_dir() -> Path:              # read-only bundled assets
def user_data_dir() -> Path:             # writable user data (created if absent)
```

- **`resource_dir()`** — frozen → folder containing `Jarvis.exe`
  (`Path(sys.executable).parent`); source → repo root
  (`Path(__file__).resolve().parent.parent`). Used for `models/` and `hud/web/`.
- **`user_data_dir()`** — frozen → `%APPDATA%\JarvisAI`; source → repo root
  (so dev is unchanged). Creates the dir if missing.

**Path migration** (constant *names* unchanged in `config/settings.py`, values
computed via the resolver):

| Today (CWD-relative) | Becomes |
|---|---|
| `VOSK_MODEL_PATH = "models/vosk/..."` | `resource_dir() / "models" / "vosk" / ...` |
| `WAKE_MODEL_PATH = "models/wake/..."` | `resource_dir() / "models" / "wake" / ...` |
| `PROFILE_PATH = "data/profile/user_profile.json"` | `user_data_dir() / "data" / "profile" / ...` |
| `semantic_memory.json`, `vector.index`, `chunks.pkl` | under `user_data_dir()` |
| tasks json, `logs/` | under `user_data_dir()` |
| `hud/web/` assets | `resource_dir() / "hud" / "web"` |

**Writable layout under `user_data_dir()`** (identical relative structure in dev
and frozen, only the base differs):
```
<user_data_dir>/
  data/profile/user_profile.json
  data/documents/...            (+ vector.index, chunks.pkl)
  data/tasks/tasks.json
  core/memory/semantic_memory.json   (kept at its current relative path)
  logs/
```
This preserves every existing relative path verbatim — only the base directory
changes when frozen — so no caller needs new path logic beyond reading the
constant from `config/settings.py`.

**Key invariant:** in source/dev mode both helpers resolve to the repo root, so
`python app.py`, existing tests, and current relative behavior are byte-for-byte
unchanged. Divergence happens only when frozen.

**Tested:** monkeypatch `sys.frozen` / `sys.executable` / `APPDATA`; pure & CI-safe.

### 3.2 `core/setup/` — first-run detection & prerequisite checks

```
core/setup/__init__.py
core/setup/checks.py      # pure-logic probes, injected deps, unit-tested
core/setup/first_run.py   # first-run trigger + orchestration
```

**`checks.py`** — each returns `{ok: bool, detail: str, fixable: bool}`:

| Check | How | Notes |
|---|---|---|
| `check_ollama_running()` | GET `http://localhost:11434/api/tags` (short timeout) | "not installed" vs "not running" where detectable |
| `check_model_present(name)` | parse `/api/tags` for the model | reuses the running-check response |
| `check_microphone()` | enumerate PyAudio input devices → count + default index | feeds mic auto-detect |
| `check_webview2()` | Windows registry probe for the WebView2 runtime | no-op `ok=True` off-Windows |

All take injected dependencies (HTTP getter, PyAudio module, registry reader) so
tests pass fakes — no real services in CI.

**`first_run.py`**
- `is_first_run()` → `True` when no profile exists at
  `user_data_dir()/data/profile/user_profile.json`. Single trigger for both
  auto-HUD and the wizard.
- `run_checks()` → ordered list of results for the wizard to render.
- `pull_model(name, on_progress)` → runs `ollama pull <name>` as a subprocess,
  streaming progress to a callback; missing `ollama` binary fails with guidance,
  not a trace. The one check that is also a fix.

### 3.3 First-run launch & HUD wizard

**`app.py main()`**
```
first_run = is_first_run()
show_hud  = args.hud or first_run
if show_hud:
    _start_hud(session, task_manager, wizard=first_run)
```
First launch → HUD opens for setup. After the profile is written, later launches
are voice-only unless `--hud`.

**Frozen-vs-source HUD launch (isolated branch in `_start_hud`)**
```
if is_frozen():
    hud.window.start_in_thread()          # in-process pywebview
else:
    subprocess.Popen([sys.executable, "-m", "hud"], cwd=...)   # unchanged dev path
```
`hud/window.py` gains `start_in_thread()` alongside its existing `__main__` entry.

**Wizard UI (`hud/web/`)** — new `wizard.js` + section in `index.html`/`style.css`:
- On a `wizard` WS message, render the four checks with live status.
- "Pull phi3 (2.3 GB)" button streams `pull_model` progress.
- Name input; "Start Jarvis" enabled once **required** checks pass.
- New WS command handlers: `run_checks`, `pull_model`, `save_name`,
  `finish_setup`. `save_name` writes the profile (flips `is_first_run()` false).

**Required vs optional:** Ollama+model and a microphone are required to finish;
WebView2 is implicitly satisfied (the HUD is rendering). Name defaults to "Boss".

### 3.4 Crash-recovery & graceful degradation

- **Ollama down → friendly retry.** Catch `ConnectionError`/timeout in
  `ollama_engine.ask_llm`; log + speak "I can't reach Ollama — is it running?";
  the loop survives and retries. Reuses `check_ollama_running()`.
- **No mic → clear message + exit.** `check_microphone()` at startup; zero input
  devices → clear spoken/printed message + clean exit (no PyAudio trace spin).
- **Model-load failure → degrade.** In the lazy `_get_model()` loaders: wake
  model missing/corrupt → clear fatal message (cannot run without it); Vosk
  missing but online → warn and run online-STT-only.
- **TTS engine re-init.** `engine._speak_thread` drops a dead engine and
  recreates it on next `speak()` so a SAPI hiccup doesn't leave Jarvis mute.

### 3.5 Microphone auto-detect

`check_microphone()` returns the chosen input device index (default, else best
available). `command()` (recognizer) and the wake listener accept that index so a
machine without an OS "default" device still works. The selection function
(given a device list) is unit-tested with a fake PyAudio.

### 3.6 Build tooling & docs

- **`jarvis.spec`** (committed) — PyInstaller `--onedir`; `--add-data` for
  `models/` and `hud/web/`; `excludes` for unused deps (per pywebview freezing
  guidance); Windows WebView2 left to the system runtime.
- **`build.ps1`** — one command → `dist/JarvisAI/` (`Jarvis.exe` + `_internal/`
  + `models/` + `hud/`).
- **README** — "Build a Windows binary": prerequisites (Ollama, WebView2),
  `build.ps1`, and a manual smoke-test checklist.

## 4. Data flow

**First run (frozen):**
`Jarvis.exe` → `is_first_run()` true → HUD launches in-process → WS `ready` →
wizard renders `run_checks()` → user pulls model (`pull_model` streams) → enters
name (`save_name` writes profile under `%APPDATA%\JarvisAI`) → `finish_setup` →
voice loop starts.

**Normal run (frozen):** `Jarvis.exe` → `is_first_run()` false → `--hud`
respected → models loaded from `resource_dir()/models`, data read/written under
`user_data_dir()`.

**Dev run (source):** `python app.py [--hud]` → resolver returns repo root for
both → identical to today.

---

## 5. Error handling

Every prerequisite failure has a defined, non-crashing outcome (§3.4). The
existing main-loop `try/except` + 1s backoff remains the backstop. The wizard
treats `pull_model` failures and unreachable Ollama as recoverable (retry
button), not fatal.

---

## 6. Testing

**Unit-tested (CI-safe, Ubuntu):**
- `core/paths.py`: `is_frozen`, `resource_dir`, `user_data_dir` via monkeypatched
  `sys.frozen` / `sys.executable` / `APPDATA`.
- `core/setup/checks.py`: each probe with injected fakes (HTTP, PyAudio,
  registry) — both ok and failure branches.
- `core/setup/first_run.py`: `is_first_run` (profile present/absent),
  `run_checks` ordering, `pull_model` argument construction (subprocess mocked).
- Mic selection: chosen index given a device list.

**Manual (documented, not in CI):**
- `build.ps1` produces `dist/JarvisAI/`.
- Smoke-test checklist: launch → first-run wizard → checks → pull → name → voice
  works → relaunch is voice-only → `--hud` shows HUD → data lands in
  `%APPDATA%\JarvisAI`.

CI: no Windows runner added; only new unit tests. Build-breaking flake8 stays 0.

## 7. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Frozen HUD launch divergence is the fiddly part | Confine to one `is_frozen()` branch + `core/paths.py`; dev path untouched |
| pywebview needs WebView2 at runtime | Wizard checks it; README lists it as a prerequisite |
| `.exe` build unverifiable in CI | Testable seams unit-tested; build manual + documented smoke-test |
| Path refactor could regress dev behavior | Resolver returns repo root in source mode; existing tests guard it |
| Bundled model size (~150 MB) | One-folder keeps models as real files (verifiable/replaceable), no temp extraction |

---

## 8. Success criteria

1. `python app.py` and `python app.py --hud` behave exactly as today (dev mode).
2. All existing tests pass; new seam tests pass; build-breaking flake8 = 0.
3. `build.ps1` yields a `dist/JarvisAI/` that launches on a clean Windows box.
4. First launch runs the HUD wizard; checks/pull/name work; profile lands in
   `%APPDATA%\JarvisAI`; later launches are voice-only unless `--hud`.
5. Each of the four failure modes degrades gracefully (no opaque crash).
